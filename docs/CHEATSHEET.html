Pitch ~45 s

English Before a farmer in Punjab loads his crop, he needs one answer: what's the price today? He has a keypad phone, he speaks Punjabi, and no app is built for him.

Kisan Helpline lets him ask the way he talks: "Amritsar mandi vich kanak da ki bhaa hai?" In under a second he hears the answer in Punjabi, with the price and the date it's from. It also covers weather and government schemes, and answers in Hindi if he asks in Hindi.

Our core rule: the bot never invents a number. No AI writes the answer. Every number comes from real data, and a checker blocks anything not in the source. If we don't know, it says so.

About 0.9 seconds per answer against a 6-second limit, 12 of 12 noisy test questions, 48 tests, zero made-up numbers. It's live, and you can upload your own data without changing code.

Database

SQLite, a single file data/kisan.db on the server. No separate DB server; built into Python; a query takes ~1 ms.

Table prices

id · state · district · market · commodity · variety · arrival_date · min_price · max_price · modal_price

Unique rule: one row per market + crop + variety + date, so no duplicates.

Table query_log

at · channel · heard · intent · crop · market · answered · answer · total_ms

Other data

  • data/schemes.json: 4 schemes, Punjabi + Hindi text, numbers, source links, date checked
  • data/synonyms.json: dictionary (kanak = ਕਣਕ = गेहूं = wheat), 26 mandis with lat/lon
  • data/sample_prices.csv: made-up test prices, loaded at start
  • data/tts_cache/: generated audio, reused
SayWe use SQLite. The database is one file, data/kisan.db, on our server, with two tables: prices and query_log. Prices load from CSV; upload yours on /admin and it goes straight into the prices table. Schemes are a JSON file; weather comes live from Open-Meteo. For a statewide rollout we'd move to PostgreSQL, and only data.py changes.

One question, start to end

  1. Farmer taps mic → browser records WAV (JavaScript)
  2. fetch("/api/ask") sends it to the backend
  3. Google ASR, Punjabi + Hindi in parallel, 5 guesses each
  4. Pick the guess that matches a real crop/mandi
  5. intent.py → {crop: wheat, mandi: Amritsar, intent: price}
  6. SQL query on kisan.db → row: 2480 ₹, 19 Nov
  7. Template sentence; check_grounded() checks every number against the row
  8. gTTS makes the MP3 (or cache)
  9. JSON back: text, source, timings, audio → browser shows and plays

Phone call

  1. Farmer calls → telecom (Twilio/Exotel) asks our server what to say
  2. Greeting → beep → record question (stops after 2 s silence, max 12 s)
  3. Same pipeline → answer played → "anything else?"
  4. Fails twice → keypad: 1 wheat, 2 paddy … 0 weather

One flow, two outputs: the call logic is written once (flow_* in phone.py). It renders as TwiML for a real Twilio call and as JSON for the simulator.

Phone-line filter: 300–3400 Hz band-pass, 8 kHz, mu-law. Your laptop voice is degraded to real call quality before recognition.

SayA Twilio trial can't buy a number any more, so we demo with a simulator that runs the exact same call logic at real phone quality. The real-call code is ready at /voice. For rollout, a free missed-call number through an Indian provider like Exotel.

Judge questions

Why no LLM?An LLM can invent numbers and is slower. Rules understand, data fills, checker verifies. Fast and trustworthy.
How do you stop wrong numbers?check_grounded() pulls every number from the sentence and matches it to the source row. Any mismatch blocks the answer.
How does it handle noise?5 guesses × 2 languages; we choose the one that matches a real crop and mandi. Keypad fallback after 2 failures.
Local words / spellings?synonyms.json + Gurmukhi "skeleton" (drops vowel signs) + fuzzy matching. kanak, ਕਨਕ, गेहूं all mean wheat.
Hindi?Devanagari script, or Hindi-only words written in Gurmukhi (ਮੇਂ, ਕਾ). Reply in the same language.
Your own dataset?Upload CSV on /admin; column names are matched flexibly; Replace or Merge. No code change.
How under 6 s?Parallel ASR, rule-based understanding (~10 ms), SQLite (~1 ms), cached audio. Timings shown on screen.
Security?Admin token for uploads, Twilio signature check, secrets in env variables.
How to scale?PostgreSQL, Bhashini, Exotel number. Each provider sits in one file.
Problems after deploy?Server is on UTC, so dates were a day behind after midnight IST → fixed with India time. Open-Meteo rate-limited Render's shared IP (429) → added wttr.in fallback.

Known limits say them yourself

  • Voice tests used synthetic voices; real farmer voices are next.
  • On phone audio, mandi names can be misheard; the bot lists mandis instead of guessing.
  • Google's free ASR is unofficial and rate-limited → Bhashini planned.
  • 4 schemes only, updated by hand with source and date.
  • Sample prices are made up; real ones come from your CSV or Agmarknet.
  • Free server sleeps after 15 min; uploaded CSV is lost on restart.
